# Phase 6.3 — OSINT / External Surface — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or executing-plans. Checkbox (`- [ ]`) steps.

**Goal:** Add OSINT discovery (registrant emails, org/whois metadata, certificate-transparency subdomains, and key-gated Shodan host data), introducing an encrypted **API-credential** pipeline so key-gated scanners can run safely.

**Architecture:** Same scanner/parser/orchestrator/persister pattern. Adds three Prisma tables (`Email`, `OrgMetadata`, `ApiCredential`), a `SecretBox`-backed credential store with GraphQL management, a scanner-sdk `requiresCredential` field + scan-worker credential injection, `emails[]`/`orgMetadata[]` channels on `NormalizedOutput`, two persisters, three scanners (`whois`, `crtsh`, `shodan`), parsers, the `osint-passive` template, GraphQL queries, a frontend OSINT tab, and an opt-in e2e. Builds on 6.1/6.2.

**Tech Stack:** Nx · NestJS · Prisma 6 · BullMQ · Apollo GraphQL · React · Zod · AES-256-GCM (`SecretBox`) · Docker.

## Refined design (6.3) — decisions locked

Refines §5.2 of `docs/superpowers/specs/2026-06-13-phase-6-recon-tooling-expansion-design.md`.

1. **Tools (this sub-phase):** `whois` (custom alpine+whois image, no key → registrant Emails + OrgMetadata), `crtsh` (alpine+curl container hitting `crt.sh` JSON, no key → certificate-transparency Subdomains), `shodan` (custom image, **needs `SHODAN_API_KEY`** → OrgMetadata; proves the credential pipeline end-to-end). **`theHarvester` and `censys` are deferred** to a follow-up (theHarvester's Python containerisation + multi-source output is its own effort; censys mirrors shodan). Documented YAGNI; emails are sourced from `whois` registrant fields, certificate-transparency subdomains from `crtsh`.
2. **`Email`** table: `id, engagementId, address (lowercased), source, firstSeenAt, lastSeenAt, metadata?`; unique `(engagementId, address)`.
3. **`OrgMetadata`** table: `id, engagementId, kind (enum OrgMetadataKind: WHOIS|ASN|ORG|NETBLOCK|OTHER), data (Json), source, firstSeenAt, lastSeenAt`; unique `(engagementId, kind, source)` (upsert refreshes `data`+`lastSeenAt`).
4. **`ApiCredential`** table: `id, ownerId (FK User), provider (enum ApiProvider: SHODAN|CENSYS), ciphertext (Bytes), createdAt, updatedAt`; unique `(ownerId, provider)`. The plaintext key is NEVER stored or returned — only `SecretBox.seal()` ciphertext.
5. **Credential pipeline:**
   - `libs/config` already validates `MASTER_ENCRYPTION_KEY`. A `SECRET_BOX` provider (a configured `SecretBox`) is exposed from a small shared Nest module (`libs/common` already has `SecretBox`; add an injectable provider in api-gateway + scan-worker built from `AppConfigService.env.MASTER_ENCRYPTION_KEY`).
   - GraphQL (api-gateway `ApiCredentialsModule`): `setApiCredential(provider, secret): Boolean` (seal + upsert by `(ownerId, provider)`), `deleteApiCredential(provider): Boolean`, `apiCredentials: [ApiCredentialInfo { provider, createdAt, updatedAt }]` (no secret field exists on the type).
   - `ScannerDefinition` gains optional `requiresCredential?: 'SHODAN' | 'CENSYS'` and `credentialEnvVar?: string`. `shodan` sets `requiresCredential: 'SHODAN'`, `credentialEnvVar: 'SHODAN_API_KEY'`.
   - **scan-worker** (`ScanJobProcessor`): if `scanner.requiresCredential`, resolve the engagement's `ownerId`, load `ApiCredential(ownerId, provider)`, `SecretBox.open()` it, and inject `{ [scanner.credentialEnvVar]: key }` into the container `env` (merged over `build.env`). If no credential exists → fail the ScanJob with a clear `errorMessage` ("missing <provider> API credential") and do NOT run the container. The key is never logged.
6. **`NormalizedOutput`** gains `emails: NormalizedEmail[]` (`{address, source?}`) and `orgMetadata: NormalizedOrgMetadata[]` (`{kind, data}`). `ProducedEntity` gains `'Email'`, `'OrgMetadata'`. crtsh reuses the existing `assets` SUBDOMAIN channel + subdomain persistence.
7. **Persisters:** `EmailPersister` (upsert by `(engagementId, address)`), `OrgMetadataPersister` (upsert by `(engagementId, kind, source)`). Wired into `parse-job.processor.ts`.
8. **Template `osint-passive`:** `crtsh → whois` (both key-free; crtsh on root target, whois on root target). shodan is standalone/opt-in (needs a key).
9. **GraphQL queries:** `emails(engagementId)`, `orgMetadata(engagementId)` (engagement-scoped, guarded, mirror endpoints module). Plus the credential mutations/query.
10. **Frontend:** an **OSINT** tab (emails list + org metadata) on the engagement page (mirrors the Endpoints tab) and an **API Keys** settings panel for `setApiCredential` (password input; never displays stored keys).
11. **Migrations:** hand-written SQL (no local Postgres). `prisma validate`/`generate` verify offline.

**Acceptance (opt-in e2e `osint-passive-e2e`, gate `E2E_RUN_OSINT`):** `osint-passive` on a target persists ≥1 Subdomain (crtsh) and ≥1 OrgMetadata (whois); re-run idempotent. A separate unit/integration test proves the credential round-trip (seal→store→open) and that scan-worker fails cleanly when a required credential is absent.

## Task 1: Email + OrgMetadata + ApiCredential models + migration

- [ ] **Step 1:** Add to `prisma/schema.prisma`:
```prisma
enum OrgMetadataKind { WHOIS ASN ORG NETBLOCK OTHER }
enum ApiProvider { SHODAN CENSYS }

model Email {
  id           String   @id @default(cuid())
  engagementId String
  address      String
  source       String
  firstSeenAt  DateTime @default(now())
  lastSeenAt   DateTime @default(now())
  metadata     Json?
  engagement   Engagement @relation(fields: [engagementId], references: [id], onDelete: Cascade)
  @@unique([engagementId, address])
  @@index([engagementId])
}

model OrgMetadata {
  id           String          @id @default(cuid())
  engagementId String
  kind         OrgMetadataKind
  data         Json
  source       String
  firstSeenAt  DateTime        @default(now())
  lastSeenAt   DateTime        @default(now())
  engagement   Engagement      @relation(fields: [engagementId], references: [id], onDelete: Cascade)
  @@unique([engagementId, kind, source])
  @@index([engagementId])
}

model ApiCredential {
  id         String      @id @default(cuid())
  ownerId    String
  provider   ApiProvider
  ciphertext Bytes
  createdAt  DateTime    @default(now())
  updatedAt  DateTime    @updatedAt
  owner      User        @relation(fields: [ownerId], references: [id], onDelete: Cascade)
  @@unique([ownerId, provider])
  @@index([ownerId])
}
```
Add back-relations: `emails Email[]` and `orgMetadata OrgMetadata[]` on `Engagement`; `apiCredentials ApiCredential[]` on `User`.

## Self-Review notes
- **Security:** API keys are sealed with AES-256-GCM (`SecretBox`) keyed by `MASTER_ENCRYPTION_KEY`; the plaintext is never persisted, never returned by any GraphQL field, and is excluded from logs. scan-worker decrypts only in-memory to inject one env var.
- **Deviations:** `theHarvester` + `censys` deferred (YAGNI; emails via whois, CT-subdomains via crtsh, key pipeline proven via shodan).
- **No-local-DB:** migration hand-written; verified via `prisma validate`/`generate`; applied in CI.
- **`crtsh` produces Subdomains** (reuses existing subdomain persistence) — it doubles as a passive CT subdomain source.
